# Presspeech 0.3.9

## Delivery authorization

- Setup now requires both focused-window Accessibility access and Quartz
  keyboard-event posting before declaring automatic delivery ready. A stale or
  separately denied posting grant can no longer make Presspeech report a paste
  that macOS silently discarded; diagnostics identify the two checks, and
  **Try Again** refreshes whichever represented TCC service is still missing.

## Model-download privacy

- Public speech-model downloads no longer inherit Hugging Face account tokens
  from `HF_TOKEN`, `HUGGING_FACE_HUB_TOKEN`, or
  `HUGGINGFACEHUB_API_TOKEN`. Presspeech removes those credentials only from
  its own process before FluidAudio can read them; the user's shell, token
  store, and other applications are unchanged.
- If that process-local removal unexpectedly fails, Presspeech refuses to
  start rather than allowing a public model request to carry an account
  credential. Diagnostics and logs contain variable names only, never token
  values.

## Clipboard privacy

- Automatic paste, focus-change recovery, **Copy Last Transcript**, and every
  copy or cut from **Try Dictation** now prepare transcript entries with
  AppKit's current-device-only option. They remain available to local
  Command-V but do not become available through Universal Clipboard.
- Transcript entries carry the standard transient and auto-generated markers
  used by cooperating clipboard managers. macOS Clipboard History,
  third-party software that ignores those markers, and other local clipboard
  readers remain separate privacy boundaries.
- A saved previous clipboard is restored with its original items and formats,
  but is republished for the current Mac only. The original cross-device scope
  is not recoverable from the snapshot, so restoration fails private rather
  than making earlier content newly available through Universal Clipboard;
  Presspeech does not add transcript markers to the restored items.
- When macOS is configured to deny Presspeech pasteboard reads, dictation still
  replaces the clipboard with the transcript but skips the optional previous-
  clipboard snapshot without attempting to read it. The restore menu identifies
  the denied access instead of reporting a generic unavailable representation.

Audio and transcription remain local. Clipboard text is not written to logs,
and these protections do not claim to prevent another local process from
reading the current pasteboard.
