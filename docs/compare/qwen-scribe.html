Presspeech vs Qwen Scribe

Both are free, open-source Apple Silicon apps that run speech recognition locally. Presspeech is a released, focused dictation app with a fixed Parakeet path and explicit paste-destination recovery. Qwen Scribe is a beta voice workspace that combines push-to-talk with local audio/video transcription, Qwen model choices, and searchable transcript history.

Presspeech and Qwen Scribe compared
Question Presspeech Qwen Scribe
Dictation and delivery Hold-to-talk or toggle, then normally paste only after confirming the same window is still focused. If it cannot verify that destination, Presspeech keeps the complete transcript on the clipboard for manual paste. Hold a configurable push-to-talk key and release to transcribe locally and paste at the cursor; a press-to-start, press-to-stop mode is also available. Its README does not describe a same-window verification contract comparable to Presspeech's.
Speech model One fixed multilingual Parakeet TDT v3 path through FluidAudio and CoreML on the Apple Neural Engine. Qwen3-ASR through MLX on the Mac's Metal GPU, with 1.7B and 0.6B model variants. The project documents fourteen supported languages, automatic or forced language selection, and vocabulary hints.
Beyond live dictation Deterministic dictionary corrections, exact voice shortcuts, filler removal, and opt-in spoken formatting. It does not transcribe audio or video files. Drag-and-drop audio/video transcription, word timestamps, SRT export, vocabulary hints, and a local web interface alongside desktop dictation. Non-WAV media requires ffmpeg.
Transcript history Recent transcript history is in memory only and clears on quit; Presspeech has no persistent transcript archive. Can save dictations to a local, searchable history, with controls to reopen, export, or delete transcripts; history can be disabled.
Privacy and network Speech recognition is local, with no account, cloud transcription, or Presspeech-authored analytics. Model downloads, optional update checks, and user-triggered links use the network; see the version-specific network inventory for published-build token and library-telemetry caveats. The project describes local Qwen3-ASR processing with no account, API key, or Qwen Scribe cloud service. Model weights and runtime dependencies are downloaded for first use; its API is documented as localhost-only with host and browser-origin checks.
System and setup Apple Silicon and macOS 14+. The signed, notarised app is about 8.4 MB; the model cache is about 500–600 MB. Apple Silicon and macOS 14+. The project lists native Python 3.12+ for its run/build setup; its packaged app installs Python dependencies and model weights on first use. ffmpeg is needed for non-WAV media.
Release maturity macOS 0.3.8 is the published, signed, and notarised release. The inspected release is v0.3.0-beta.1, published 4 September 2026 as an ad-hoc-signed, non-notarised build. macOS may require approving it in System Settings → Privacy & Security → Open Anyway.
Price and license Free and MIT licensed. Free and Apache-2.0 licensed.
Performance evidence Publishes model-only p50 latency of 92–152 ms across documented M4 synthetic clips; clipboard and paste are not timed. No directly comparable Qwen latency or accuracy benchmark was identified; this does not establish an accuracy or end-to-end speed winner.

Choose Qwen Scribe if you want local file/video transcription, Qwen model variants, vocabulary hints, or a searchable transcript archive in one beta app. Choose Presspeech if you want the currently released and notarised Mac build, a small fixed dictation pipeline, no persistent transcript archive, or a documented fallback when the original paste destination cannot be verified. Both projects describe local recognition; their documented workflow, retention, and release maturity differ.

Sources: Presspeech source and platform documentation, Presspeech privacy and network documentation, and Presspeech benchmarks; Qwen Scribe's source and README, v0.3.0-beta.1 release and provenance, and privacy notes (checked 23 September 2026). No cross-product latency or accuracy winner is claimed because there is no controlled head-to-head benchmark.
