Privacy

Privacy model

Presspeech is local-first in the strict sense: no analytics SDK, no accounts, no crash reporter, no transcript sync, and no cloud transcription endpoint.

What happens to the audio

Transcript handling

In memory

Audio is captured while the hotkey is active, transcribed locally, then discarded.

Paste at cursor

The finished text normally goes through the platform clipboard and a synthetic paste shortcut. On macOS, Presspeech falls back to direct Unicode key events if clipboard paste setup fails.

Clipboard persistence

Each recording is bound to the window focused when it began. If focus changes or Presspeech cannot verify the same destination, it leaves the transcript on the clipboard for deliberate manual paste instead of risking delivery to the wrong window. macOS leaves the transcript on the pasteboard by default. Published macOS 0.3.7 offers an off-by-default automatic restore; leave it off if a slow app receives older clipboard contents. Upcoming 0.3.8 / builds containing Keep Previous Clipboard for Manual Restore: the new off-by-default option keeps an eligible complete previous clipboard snapshot only in memory for up to five minutes. A snapshot is limited to 64 MB and 256 representations; no partial snapshot is offered when a limit is exceeded or a representation is unavailable. Consecutive dictations keep the original deadline. It restores only after you choose Restore Previous Clipboard…, verify the paste arrived and confirm, while clipboard ownership still matches. Expiry, another copy, disabling the option or quitting discards the saved snapshot without rewriting the clipboard. The retired automatic timer preference does not enable this new retention option. Confirmation is a user decision, not an operating-system acknowledgement. See the recovery guide. Windows leaves the transcript on the clipboard until something else is copied. Upcoming Windows 0.1.13: unsuccessful or uncertain delivery keeps a recovery copy only in process memory until an explicit verified Copy, Discard, or Exit. The keyboard-accessible Delivery Recovery window does not display the words or copy them automatically; a blocked hotkey or another launch only brings the window back. Depending on where delivery became uncertain, text may already be in the field or clipboard. Recording waits for review. Every normal or recovery clipboard write first adds Microsoft's history/cloud exclusion format, so Windows is instructed not to retain or sync the item through Clipboard History or Cloud Clipboard. The current item remains available to Ctrl+V and other local clipboard readers; no transcript contents are written to logs, settings or recovery files.

Operating-system clipboard services

“No transcript sync” describes Presspeech itself, not services that monitor the general clipboard. On macOS 26 or later, enabled macOS Clipboard History in Spotlight makes earlier copied items searchable; Apple notes that sensitive information may appear there and provides Clipboard → More → Clear History. With Handoff enabled, macOS Universal Clipboard can also make copied content available on nearby Apple devices. Published Windows 0.1.12 writes can be retained by Windows Clipboard History or synced through its cross-device setting. Upcoming Windows 0.1.13 uses Microsoft's documented clipboard exclusion format to opt every dictation write out of both services. Third-party clipboard managers and other local readers may still retain the current entry. Review Spotlight Clipboard History and System Settings → General → AirDrop & Handoff on macOS, or local clipboard software on Windows, before sensitive dictation.

No transcript logs

Logs include timing and length metadata only. Transcript content is not written to disk.

Sandbox surface

Permissions and entitlements

The notarised macOS app uses two hardened-runtime entitlements: audio input and microphone. macOS also requires user-granted Accessibility and Input Monitoring permissions for the hotkey and paste workflow.

The macOS app does not add JIT, unsigned executable memory, library-validation, network-client, contacts, calendar, location, camera, or file-provider entitlements.
