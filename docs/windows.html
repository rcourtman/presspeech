Windows prerelease

Private dictation on your Windows PC

Hold Right Alt, speak, and release. Presspeech transcribes on your PC and normally pastes into the window where you started; if it cannot verify that destination, it avoids automatic paste. A switch to another field or browser tab in the same window may still send text to the new focus without a recovery notice, so keep the starting field and tab selected until delivery finishes. Published 0.1.12 copies the result to the clipboard for manual paste. Upcoming 0.1.13 instead opens Delivery Recovery for an explicit Copy or Discard when delivery is uncertain; a known-invalid target leaves the previous clipboard item alone. There is no account or cloud transcription.

Privacy decision for published Windows 0.1.12: model downloads may send Hugging Face usage telemetry or an available token. If you prefer to avoid this possible usage telemetry, are concerned that a Hugging Face token or custom download route may be configured on this PC, or are unsure, leave 0.1.12 unopened and wait for Windows 0.1.13 before use. If a TLS-inspecting HTTPS proxy is in use and its trust is unclear, don't launch while it is in use.

Why: during model downloads, its Hugging Face libraries may send default usage telemetry and include a token already available to this Windows account. Custom download routing can change where the model request—and a token it carries—goes. A TLS-inspecting HTTPS proxy trusted by the client can read any 0.1.12 token it receives. Upcoming 0.1.13 removes account-token authentication but still honors proxy and CA settings. The public models need no account token.

Downloading or installing is not launching: downloading the installer and checksum from GitHub or installing without opening Presspeech does not make a model request. A missing selected-model download starts when 0.1.12 launches; this build has no Set Up Later option to defer it. If you install 0.1.12 but choose to wait, leave Launch Presspeech unchecked on the installer’s final screen and do not open the app. Dictation audio and transcripts are not sent in model downloads.

Already used Windows 0.1.12? If a model download ran with a token available and an inherited HF_ENDPOINT or staging setting may have sent it to a destination you do not trust—or an untrusted TLS-inspecting HTTPS proxy could read the request—treat the token as disclosed to that destination or proxy. A proxy that only tunnels HTTPS cannot read the token. Revoke the token and create a replacement at Hugging Face Access Tokens; do not include token values in logs or support requests.

Technical details of Windows 0.1.12 model downloads

Privacy for published Windows 0.1.12: Hugging Face libraries’ default usage telemetry and implicit authentication remain enabled during model downloads. The libraries may send usage data to Hugging Face, and model-request metadata includes a random per-process session ID. Its pinned Hub 1.29.0 client may fetch /api/agent-harnesses when its local registry cache is missing or stale, and inherited agent-related environment markers may add an agent/<id> label to model-request metadata. An available HF_TOKEN, HUGGING_FACE_HUB_TOKEN, or token in the local Hugging Face cache may accompany a model request. This build also honors inherited HF_ENDPOINT and HUGGINGFACE_CO_STAGING settings, which can change the request destination; an available token may therefore go to that configured endpoint. If HF_HUB_USER_AGENT_ORIGIN is set, its value is added to request metadata. These models do not require an account token. Upcoming 0.1.13 fixes those inherited settings, disables Hub telemetry before imports, and checks that rendered headers contain no agent label; it is not yet published. Both published Windows 0.1.12 and upcoming Windows 0.1.13 use HTTPX 0.28.1 with the Hub client's default trust_env=True; it honors HTTP_PROXY, HTTPS_PROXY, ALL_PROXY, NO_PROXY, SSL_CERT_FILE, and SSL_CERT_DIR. A TLS-inspecting HTTPS proxy whose CA is trusted by the client can read request headers and any 0.1.12 token; a tunnelling proxy sees connection metadata, not request contents. Upcoming 0.1.13 still honors these proxy and CA settings. Published Windows 0.1.12 does not independently verify model-file contents against SHA-256. Upcoming Windows 0.1.13 verifies every allowed required and present optional inference file before model loading by checking it against its pinned SHA-256 manifest. A local verification record is reused only while file identity and metadata remain unchanged; files without a matching record are rehashed, and mismatches fail closed. The proxy can still observe request metadata or block a download. Dictation audio and transcripts are not sent in model downloads; the exact telemetry fields are not independently itemised.

See the version-specific network-call inventory.

Install safely

Download, verify, and run

Presspeech remains compatible with Windows 10 x64, but Microsoft ended general Windows 10 support on 14 October 2025. Prefer Windows 11, or use Windows 10 only with Extended Security Updates or an edition that remains supported.

  1. Download the current installer and checksum

    Get Presspeech-Setup-0.1.12-x64.exe and its published SHA-256 file from the same GitHub release.

  2. Verify SHA-256 automatically

    In PowerShell, run the commands below from your Downloads folder. They validate the checksum file, compare it with the installer, and stop with an error instead of reporting success if anything differs. This confirms the installer matches the checksum published alongside it; because both files come from the same release, the checksum alone does not independently authenticate the publisher or make an unsigned installer trusted. If you cannot decide to trust this release, stop here.

    $installer = '.\Presspeech-Setup-0.1.12-x64.exe'
$parts = (Get-Content -LiteralPath "$installer.sha256" -Raw).Trim() -split '\s+'
if ($parts.Count -ne 2 -or
    $parts[0] -notmatch '^[0-9a-fA-F]{64}$' -or
    $parts[1] -ne (Split-Path $installer -Leaf)) {
  throw 'The published checksum file is not valid. Do not run the installer.'
}
$actual = (Get-FileHash -LiteralPath $installer -Algorithm SHA256).Hash
if ($actual -ne $parts[0]) {
  throw 'SHA-256 verification failed. Do not run the installer.'
}
"SHA-256 verified: $actual"
  3. Optionally verify the immutable release attestation

    If you already use an authenticated GitHub CLI, these commands additionally check that GitHub considers the release immutable and that your local installer matches its signed release attestation:

    $ErrorActionPreference = 'Stop'
gh release verify windows-v0.1.12 --repo rcourtman/presspeech
if ($LASTEXITCODE -ne 0) { throw 'Release attestation failed; do not run the installer.' }
gh release verify-asset windows-v0.1.12 $installer --repo rcourtman/presspeech
if ($LASTEXITCODE -ne 0) { throw 'Installer attestation failed; do not run the installer.' }
'Release and installer attestations verified.'

    The success line appears only if both commands succeed. If either fails, stop: do not treat the installer as attested or run it until you resolve the failure. This provides stronger provenance evidence than the checksum file hosted beside it, but does not code-sign the installer or override Windows security policy.

  4. Run the installer

    The current build is unsigned. If Microsoft Defender SmartScreen shows Windows protected your PC, confirm the filename and verified hash before choosing More info → Run anyway. That choice applies to a SmartScreen reputation warning, not a Smart App Control block: Smart App Control has no per-app exception. If Smart App Control or your administrator blocks the installer, stop; do not disable protection or work around the block.

  5. Decide whether to launch 0.1.12

    If you chose to wait after reading the privacy decision, leave the installer’s final Launch Presspeech option unchecked and do not open the app. If you choose to use published 0.1.12 now, open it from the Start Menu; a missing model starts downloading without another prompt. It installs for your user account under %LOCALAPPDATA%\Programs\Presspeech and appears in Settings → Apps → Installed apps for normal removal.

Why the warning? Microsoft explains that unsigned downloads start without publisher reputation; each new unsigned version may prompt again.

First launch

Check model preparation before dictating

  1. Check the selected path

    Presspeech tests the packaged CUDA runtime. A usable NVIDIA setup selects multilingual Parakeet TDT v3; without usable CUDA, a fresh installation selects Whisper base.en for CPU use. Published 0.1.12 starts the selected missing-model download when you launch it, without another prompt. Upcoming 0.1.13 asks before downloading missing first-run default model files: Parakeet (up to ~2.5 GB) or English-only Whisper base.en on CPU (~141 MiB). Only in that upcoming build can you defer the first download from Setup; its Parakeet path also offers the smaller CPU model. A complete local snapshot loads without a model download.

  2. Let preparation finish

    Published 0.1.12: Setup shows model preparation, microphone selection and its automatic check, a selectable dictation hotkey, global-listener status, and Start Presspeech with Windows. On a new profile, startup is selected by default; turn it off before choosing Finish Setup, Set Up Later, or closing Setup if you do not want the app at sign-in. Hold to talk is the default. To use Press to toggle, finish Setup, open Settings, select Press to toggle under Trigger, then save; 0.1.12 does not offer dictation style in Setup. A missing model has already started downloading on launch: Set Up Later defers completing setup, not that download. Microphone and hotkey choices apply immediately, including in Try Dictation. That test becomes available when the model is ready; Finish Setup also requires the global hotkey to be ready. If preparation fails, choose Retry Speech Model. Deferring leaves setup incomplete; the window opens again on the next launch with your microphone, hotkey, and startup choices kept. You can finish after the model is ready even if you plan to connect a microphone later.

    Upcoming 0.1.13 (not yet published): Setup also offers Hold to talk or Press to toggle and keeps that choice if you defer setup. A new profile starts with Start Presspeech with Windows off; opt in if you want Presspeech ready after sign-in. Before downloading a missing first-run model, Setup discloses the default size and asks you to choose: about 2.5 GB for multilingual Parakeet from huggingface.co with usable CUDA, or about 141 MiB for English-only Whisper base.en on CPU. You can choose the offered download, another model in Settings, or Set Up Later; the Parakeet path also offers the smaller CPU model. Its microphone stays closed until you choose Check Microphone, and changing the selected input does not start a check. These first-run changes are not in published 0.1.12.

    If Right Alt enters @, €, or accented letters on your keyboard, Windows is using it as AltGr; choose F8 or another hotkey so AltGr remains available for typing. For keyboard-only use, press Left Alt with a command's underlined letter; Escape closes the current Presspeech window, and Ctrl+S saves Settings. If Windows refuses startup registration, Finish Setup stays open and reports the failure; choose Open Startup Settings to review Presspeech under Settings → Apps → Startup, then retry Finish Setup. In upcoming 0.1.13, Set Up Later shows a warning and closes while leaving setup incomplete, so it reopens on the next launch.

  3. Check microphone access

    Published Windows 0.1.12 checks the selected input during setup and when its selection changes; the retry action is Check Again. Upcoming 0.1.13 and builds containing this change leave the microphone closed until you choose Check Microphone. In either version, a readiness check briefly opens the selected input to measure its level; samples stay in memory and are discarded, not saved, sent, or transcribed. Windows may show its microphone-use indicator while the input is open. On some Windows 11 builds, first access may also show a Windows microphone-permission prompt; approve it only if you want Presspeech to use the microphone. If the check detects no input level, unmute the selected microphone, speak, and repeat with Check Again in 0.1.12 or Check Microphone in 0.1.13. If the microphone cannot be opened, use the direct buttons to open Windows Microphone Privacy or Sound Input settings. Turn on Microphone access, Let apps access your microphone, and Let desktop apps access your microphone, confirm the input, then check again. Some Windows 11 Experimental builds also offer per-app microphone controls for desktop apps; if that setting is present, allow Presspeech there too. If Windows says the shared settings are managed by your organization, contact your administrator; Presspeech cannot override that policy. After reconnecting a USB or Bluetooth microphone, choose Check Again in 0.1.12 or Check Microphone in 0.1.13 to refresh device discovery without an app restart; a specifically selected unavailable input remains selected instead of silently changing to another microphone. Before opening the microphone for each recording, Presspeech confirms that its cached Windows audio-device index still names the configured microphone and remains an allowed input, rejecting a stale entry when re-enumeration shows that indexes changed after reconnect or resume. On standard Windows builds, desktop apps use shared microphone privacy control; builds that offer per-app desktop controls can expose a Presspeech toggle. Outside a readiness check, Presspeech captures audio only while dictation is active; all captured audio is discarded after local processing.

  4. Try the in-app test with harmless words

    Open the tray menu and choose Try Dictation…. The scratchpad is in-app, but it is not isolated from the system clipboard; see the clipboard warning before practicing. With Hold to talk, hold the hotkey shown in Presspeech, speak, and release; with Press to toggle, press once to start and again to stop. Check the result without pasting into another app. The hotkey is Right Alt by default, or the alternative you selected during setup, such as F8 on an AltGr keyboard.

Everyday use

Hold, or press to toggle.

Dictate in your apps

Hold Right Alt by default, speak, and release to transcribe. To avoid holding a key throughout a recording, choose Press to toggle in Settings (also in Setup in the upcoming 0.1.13 build): press once to start and again to stop. The notification-area menu's Dictate action also starts and stops recording without the configured key, in either dictation style. Published 0.1.12 plays its high cue before the microphone opens, so allow time for the device to start before speaking. Upcoming 0.1.13 shows Connecting microphone… until the first input buffer arrives; its high cue then confirms input is arriving, and Listening… appears after the cue and playback-muting step when Presspeech begins accepting speech. If a press ends before that readiness point, it reports Microphone was not ready; a started input with no buffers reports a microphone error. If a ready recording captures too little audio or Whisper VAD rejects it, the indicator briefly says No speech detected — try again and a Windows notification points back to Setup's microphone check. If the recognizer instead returns blank text without VAD-zero evidence, it says No text recognized — try again; that result does not establish that the microphone captured silence. The configured key is reserved for Presspeech while it is running, so it does not also open a Windows surface or invoke an F8–F12 command in the focused app; other keys and AltGr layout input continue to pass through normally. Press Escape during recording to cancel and discard the buffered audio without transcribing or changing the clipboard. The notification-area menu offers the same Cancel Dictation (Esc) action while recording. If Windows hides that icon in overflow, launch Presspeech again from the Start Menu to restore its window or open its controls; a second dictation process is not started. If the configured key stops responding while menu-based Dictate still works, choose Repair Global Hotkey in the notification-area menu, Setup, or Settings. Presspeech replaces the listener even when its thread still appears healthy and reports whether the replacement started. Hotkeys, hold/toggle behavior, microphone, text suffix, audio cues, models, and the 1/2/5/10-minute maximum recording length are configurable. Parakeet recordings longer than 60 seconds use overlapping model inputs capped at 60 seconds; token timestamps crop each result to its owned interval rather than guessing at repeated transcript strings. A microphone selection saved during a recording applies to the next dictation; the active recording stays on the input it opened so its timing and final words remain intact. Reaching the configured limit stops and transcribes rather than discarding the recording. Saving a different model starts preparing it immediately; Settings keeps its ready/error status visible and offers a retry, while dictation stays unavailable until preparation finishes.

Window focus, with limits

A recording is bound to the window where it began. If focus changes to another window during transcription, Presspeech will not paste into that new window. This does not always identify a different field or browser tab in the same window; keep the original field and tab selected until insertion or recovery. Published 0.1.12 leaves the text on the clipboard and notifies you when the window check fails. Windows blocks a standard app from sending the paste shortcut into a target running as administrator. Published 0.1.12 also leaves that transcript on the clipboard for manual paste; do not elevate Presspeech as a workaround. Upcoming 0.1.13: an already-known missing, unfocused, or elevated original target leaves the prior clipboard item unchanged, as does an unreadable Presspeech integrity level when the target level is known. Both paths open a keyboard-accessible Delivery Recovery window with explicit Copy, Discard and Leave Waiting actions. A failed or inconsistent Windows focused-control query also uses Delivery Recovery, even when both checks concern the same foreground window; if known before copying, the previous clipboard item stays unchanged. A completed query with no child control still cannot prove which browser field or tab is selected. The window does not display or implicitly copy the dictated words. If you close Recovery while a dictation is waiting, the Try Dictation scratchpad offers Review Delivery… to reopen it without copying. A change after that preflight may still leave the transcript on the current clipboard. If a clipboard write fails after replacement begins, Windows cannot restore the prior item; Presspeech clears its partial item while it still owns the clipboard and retains the dictation for explicit recovery. If cleanup fails, text may remain on the current clipboard.

Review commands before running them

PowerShell, Command Prompt, Windows Terminal, and remote consoles are execution surfaces, not ordinary text fields. The default After pasting value is space; selecting newline can submit a transcript immediately. Dictate command text into Try Dictation or a plain-text editor, review it, then paste and run it deliberately. Do not rely on a terminal warning: Windows Terminal documents that pasted newlines can execute commands, and its warning depends on settings.

Clipboard history and sync

Presspeech does not sync transcripts, but normal and recovery delivery writes finished text to the Windows clipboard. A write replaces the current clipboard item, including an image or formatted copy; Presspeech does not restore it after pasting. In upcoming 0.1.13 Delivery Recovery, choose Leave Waiting if you need to save the current item before choosing Copy for Manual Paste. Published 0.1.12 writes can enter Clipboard History or cross-device sync. Upcoming 0.1.13 adds Microsoft's ExcludeClipboardContentFromMonitorProcessing format before text on every dictation clipboard item, including Copy and Cut from Try Dictation, instructing Windows not to retain the item in Clipboard History or Cloud Clipboard. The text remains on the current clipboard for Ctrl+V, where another local process or third-party clipboard manager may still read it. Clipboard History or a third-party manager is not a guaranteed way to recover a prior item.

Remote desktop aware

Moonlight and Microsoft Remote Desktop receive different remote-delivery handling. RDP requires client-to-remote plain-text clipboard redirection to be allowed; Presspeech cannot bypass a client or host restriction. Moonlight uses its client-side shortcut to type local clipboard text into the remote session instead of synchronizing a remote clipboard. Both routes can send the text to the remote host. Try harmless text in a blank, non-submitting remote editor and inspect the result before relying on the route. Normal Windows apps retain the standard fast Ctrl+V path. See Microsoft's RDP clipboard guidance and the target-app compatibility check.

Updates require approval

Optional update checks read public GitHub release metadata and ignore releases that are not marked immutable. Presspeech downloads an installer only after approval, then verifies its published size and SHA-256 before offering to run it.

Privacy

Speech stays on the PC

No transcription service

Model files download from pinned revisions during setup, but dictation audio is not uploaded. Published Windows 0.1.12 honors inherited HF_ENDPOINT/HUGGINGFACE_CO_STAGING routing and may send a locally available Hugging Face token to the configured endpoint; it can also add HF_HUB_USER_AGENT_ORIGIN to request metadata. Upcoming 0.1.13 fixes the endpoint, removes the inherited origin, declines account tokens, disables the bundled model libraries' telemetry and implicit authentication, and bypasses the separate hf-xet transfer client before they load. There is no Presspeech account, analytics SDK, crash reporter, or transcript history.

Diagnostics omit your words

Copy Diagnostics reports runtime state, timings, and character counts. It excludes transcript text, audio, and dictionary contents.

Start with the Windows recovery guide. The Windows technical guide covers every setting, model choice, source setup, testing, packaging, and diagnostics. Copy Diagnostics copies a privacy-safe summary locally; it does not send or submit it. Report a Problem… and Suggest an Improvement… in the tray menu open the repository's support guide, not an issue form. Follow that guide for the current public-reporting status and privacy-safe draft steps. If a public route becomes available, include reproduction steps, Windows version, CPU, GPU and driver when present, and whether the model reached Ready. Upcoming 0.1.13 / builds containing Test App Compatibility… can open the repeated target-app protocol directly.

Feedback availability checked 23 September 2026: GitHub currently restricts creating new issues in this repository, so a new public report cannot be submitted there. Check for a matching existing issue and whether comments are available. Otherwise keep the privacy-safe draft local and retry when issue creation is available; do not post private data elsewhere as a workaround.

GitHub issues are public. Do not add dictated text, audio, dictionary contents, credentials, or other private data. Use the private vulnerability-reporting form for a security issue.
