Target-app check

Test Presspeech with one app

Automatic paste depends on the destination and its focus behavior. Use blank disposable fields to check one exact app and version before relying on it for real work. The check records outcomes, never your words.

Published-build privacy check (23 September 2026): The current downloads are macOS 0.3.8 and Windows 0.1.12. Both start a missing-model download on launch. The macOS request may include an inherited Hugging Face token; the Windows request may send Hugging Face usage telemetry or a locally available token, with additional routing and proxy risks. Read the macOS model-download warning or Windows model-download warning before launching or triggering a model download. If you are unsure about those version-specific risks, wait for 0.3.9 or 0.1.13 to be published rather than launching solely for this check. If your model is already ready, do not reset its cache or switch models for this protocol.

Scope

Separate insertion from recognition

Presspeech binds each recording to the window where it began. It should paste only when it can still verify that destination. A focus change normally leaves the transcript available for manual paste. On macOS, if Presspeech detects another copy replacing the clipboard during delivery, it stops and preserves that newer copy; 0.3.8 shows Couldn't paste, while builds with revised wording say Delivery uncertain. A failed input event does not prove that no text reached the destination, so inspect the target before retrying or using Copy Last Transcript.

This is a delivery check, not a transcription-quality test. The recognized wording can differ from what was spoken and still pass: the question is whether the same finished transcript reaches the intended field once, or is recovered safely without reaching another field.

Prepare safely

Before testing

  1. Finish Presspeech setup

    Read the published-build privacy check above before launching or downloading a model. Use the current official build. On macOS, this baseline requires 0.3.8 or later; update before testing if the About window shows 0.3.7. Confirm the model is ready, the microphone and hotkey checks pass, and Try Dictation works first.

  2. Open two disposable fields

    Use one blank field in the target app and one blank field in a local scratch app. Never use a production message, document, account, command shell, or field where pasted text can submit, send, or execute. Test a remote/virtual environment or terminal-based editor only when it is isolated, disposable, and non-executing; otherwise skip that target.

  3. Use harmless, distinct phrases

    Create a different phrase for every attempt so stale or duplicate delivery is visible. Do not use names, credentials, commands, customer data, or text from real work.

    Optional eight-phrase prompt

    If English suits the selected language hint, use these in order: amber rabbit one; blue otter two; copper robin three; green badger four; ivory falcon five; purple fox six; silver heron seven; yellow turtle eight. Otherwise use the same colour-animal-number pattern in the test language. Recognition accuracy is not scored; compare the finished target text with the scratch paste. Never add either version to the public report.

  4. Make clipboard behavior comparable

    On macOS 0.3.8 and later, leave Keep Previous Clipboard for Manual Restore off for this baseline. Published Windows 0.1.12 leaves the finished transcript on the current clipboard. Upcoming Windows 0.1.13 marks that item for exclusion from Windows Clipboard History and Cloud Clipboard; published 0.1.12 does not. macOS 0.3.8 can expose transcript entries to macOS Universal Clipboard; disable Handoff if the harmless test text must stay on the Mac. Builds containing local-only transcript clipboard writes prevent Universal Clipboard transfer while preserving local Command-V. If macOS Clipboard History in Spotlight is enabled on macOS 26 or later, clear it after the check if you do not want the text retained there. Also disable third-party clipboard managers if you do not want the test text retained elsewhere.

  5. Record versions, not private context

    Note the Presspeech, operating-system, and target-app versions. Classify the target as native, browser/web editor, Electron/Chromium, terminal, remote desktop/virtual machine, or elevated Windows app, and record the generic field type (for example, plain text, rich text, or browser content editor). Note the active keyboard layout/input source only if it differs from your usual layout or helps explain an outcome; record its public name, never typed content. Omit account, server, document, tab, form, and window names.

Checks 1–5

Keep the target focused

Run five completed attempts with a different harmless phrase each time.

  1. Start in the blank target field

    Keep its window focused from the start of recording until Presspeech finishes. Do not copy anything or allow a clipboard tool to replace its contents during delivery.

  2. Dictate once, then inspect the target

    Note whether one copy appeared and whether Presspeech showed a copied/manual-paste recovery notice.

  3. Inspect the clipboard before copying anything else

    If delivery succeeded or Presspeech showed its copied/manual-paste notice, paste into the separate local scratch field before copying anything else. With restoration off and no intervening clipboard change, this should be the finished transcript. After a delivery warning on macOS, do not assume the clipboard contains the transcript or that the destination received nothing: inspect the target before retrying. If text is missing, use Copy Last Transcript if offered, removing any partial text before pasting the full transcript. If Recent Transcripts is off, there is no in-app copy-recovery entry; correct or remove partial text before dictating again. Record the failed delivery; deliberate recovery afterward does not turn it into a successful attempt.

  4. Classify one outcome

    Use the definitions below, then clear both disposable fields before the next attempt.

Pasted once

The target received one copy, no recovery notice appeared, and its text matches the scratch copy, including the configured space or newline suffix.

Recovered safely

The target received nothing, Presspeech showed its copied/manual-paste notice, and the scratch paste recovered the complete finished transcript.

Incorrect or unsafe

Text was stale, partial, duplicated, unavailable, delivered elsewhere, or paste failed without a recovery notice. Stop before trying a real document.

If you know another copy changed the clipboard during delivery, record that attempt as an interruption under Relevant conditions and repeat with a fresh harmless phrase. Exclude known interruptions from the five completed-attempt counts. Do not use this exclusion for unexplained failures; report those as Incorrect or unsafe above.

Keep recovery separate from automatic paste. Manual-paste recovery is safe behavior, but counting it as an automatic-paste pass would hide app classes where insertion is consistently unavailable. The three aggregate outcome counts should total five.

Checks 6–8

Move focus before dictation finishes

Use blank disposable fields in two separate windows. Start dictation in the first window, move focus to the second, then finish. In hold mode, move before releasing the hotkey; in toggle mode, move before the stop press.

With no intervening clipboard change

  • No text is inserted into either field.
  • Presspeech shows the copied/manual-paste notice.
  • The complete transcript is available for deliberate manual paste.

Repeat three completed attempts

Record known clipboard-change interruptions separately as above. For an Electron/Chromium app, use two separate windows of that same app for at least one attempt. Same-process windows are a distinct identity check; tabs or fields in one window are not a substitute.

Classify each slot as copied for manual paste without inserting anywhere, inserted into a field, no insertion, but recovery failed, or not completed. Recovery failed means a completed attempt inserted nowhere but the notice or complete transcript was unavailable; it is an incorrect result, not an unrun check. The four counts should total three.

An older six-count draft may combine failed recovery and unrun slots as Other or not completed. If that count is zero, both new counts are zero. If it is nonzero, do not guess or present the draft as a comparable seven-count baseline. Keep it private and, if safe, rerun the protocol using the current categories.

Stop on unexpected insertion. Text reaching either test window or any unrelated destination is a safety failure. Do not retry in a real document. Mark the attempted slot as inserted and each unrun slot as not completed. Use the private reporting route if the behavior could expose or execute sensitive content.

Interpret the result

Keep platform boundaries separate

Clipboard behavior

Leave optional macOS clipboard restoration off for this baseline. On macOS 26 or later, enabled macOS Clipboard History in Spotlight can make earlier copies searchable. macOS 0.3.8 can make transcript entries available through macOS Universal Clipboard; builds containing local-only transcript clipboard writes prevent that transfer. Published Windows 0.1.12 does not opt out of Windows clipboard history or cross-device sync. Upcoming Windows 0.1.13 opts its writes out of both Windows services. third-party managers remain a separate local boundary on either platform. Review the clipboard privacy boundary.

Elevated Windows apps

Windows restricts synthetic input to targets at an equal or lower integrity level. A normally running app therefore cannot send the paste shortcut into a target running as administrator. A copied/manual-paste notice is the expected security boundary. Do not elevate Presspeech as a workaround.

Remote and specialist targets

Remote desktop, virtual machine, terminal-based editor, browser editor, and assistive-technology paths are useful reports only when the field is isolated, disposable, and cannot submit or execute a paste. An ordinary command-shell prompt is outside this community protocol. Identify the class without sharing host names, commands, account names, document titles, or private paths.

Clipboard restoration regression

If previous clipboard content is inserted, turn restoration off, remove the unintended text, and follow the recovery guide. Report that as a bug rather than a compatibility pass.
