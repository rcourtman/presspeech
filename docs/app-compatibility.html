Target-app check

Test Presspeech with one app

Automatic paste depends on the destination and its focus behavior. Use blank disposable fields to check one exact app and version before relying on it for real work. The check records outcomes, never your words.

Scope

Separate insertion from recognition

Presspeech binds each recording to the window where it began. It should paste only when it can still verify that destination; otherwise it should leave the complete transcript on the clipboard and explain how to paste it manually.

This is a delivery check, not a transcription-quality test. The recognized wording can differ from what was spoken and still pass: the question is whether the same finished transcript reaches the intended field once, or is recovered safely without reaching another field.

Prepare safely

Before testing

  1. Finish Presspeech setup

    Use the current official build. Confirm the model is ready, the microphone and hotkey checks pass, and Try Dictation works first.

  2. Open two disposable fields

    Use one blank field in the target app and one blank field in a local scratch app. Never use a production message, document, terminal, remote session, form that can submit, or account.

  3. Use harmless, distinct phrases

    Create a different phrase for every attempt so stale or duplicate delivery is visible. Do not use names, credentials, commands, customer data, or text from real work.

  4. Make clipboard behavior comparable

    On macOS, turn Settings → Behavior → Restore clipboard after paste off; it is off by default. Windows always leaves the finished transcript on the clipboard. If macOS Clipboard History in Spotlight is enabled on macOS 26 or later, clear it after the check if you do not want the harmless text retained there. Also disable macOS Universal Clipboard through Handoff, Windows clipboard history or cross-device sync, and third-party clipboard managers if you do not want the test text retained elsewhere.

  5. Record versions, not private context

    Note the Presspeech, operating-system, and target-app versions. Classify the target as native, browser/web editor, Electron/Chromium, terminal, remote desktop/virtual machine, or elevated Windows app. Omit account, server, document, tab, and window names.

Checks 1–5

Keep the target focused

Run five attempts with a different harmless phrase each time.

  1. Start in the blank target field

    Keep its window focused from the start of recording until Presspeech finishes.

  2. Dictate once, then inspect the target

    Note whether one copy appeared and whether Presspeech showed a copied/manual-paste recovery notice.

  3. Inspect the clipboard before copying anything else

    Paste into the separate local scratch field. With clipboard restoration off, this is the finished transcript used for comparison.

  4. Classify one outcome

    Use the definitions below, then clear both disposable fields before the next attempt.

Pasted once

The target received one copy, no recovery notice appeared, and its text matches the scratch copy, including the configured space or newline suffix.

Recovered safely

The target received nothing, Presspeech showed its copied/manual-paste notice, and the scratch paste recovered the complete finished transcript.

Incorrect or unsafe

Text was stale, partial, duplicated, unavailable, delivered elsewhere, or paste failed without a recovery notice. Stop before trying a real document.

Keep recovery separate from automatic paste. Manual-paste recovery is safe behavior, but counting it as an automatic-paste pass would hide app classes where insertion is consistently unavailable. The three aggregate outcome counts should total five.

Checks 6–8

Move focus before dictation finishes

Use blank disposable fields in two separate windows. Start dictation in the first window, move focus to the second, then finish. In hold mode, move before releasing the hotkey; in toggle mode, move before the stop press.

The safe result

  • No text is inserted into either field.
  • Presspeech shows the copied/manual-paste notice.
  • The complete transcript is available for deliberate manual paste.

Repeat three times

For an Electron/Chromium app, use two separate windows of that same app for at least one attempt. Same-process windows are a distinct identity check; tabs or fields in one window are not a substitute.

Classify each attempt as copied for manual paste without inserting anywhere, inserted into a field, or other/not completed. The three counts should total three.

Stop on unexpected insertion. Text reaching either test window or any unrelated destination is a safety failure. Do not retry in a real document. Use the private reporting route if the behavior could expose or execute sensitive content.

Interpret the result

Keep platform boundaries separate

Clipboard behavior

Leave optional macOS clipboard restoration off for this baseline. On macOS 26 or later, enabled macOS Clipboard History in Spotlight can make earlier copies searchable; Universal Clipboard can make them available on nearby Apple devices. Windows clipboard history, cross-device sync, and third-party managers can also retain or sync the harmless text independently of Presspeech. Review the clipboard privacy boundary.

Elevated Windows apps

Windows restricts synthetic input to targets at an equal or lower integrity level. A normally running app therefore cannot send the paste shortcut into a target running as administrator. A copied/manual-paste notice is the expected security boundary. Do not elevate Presspeech as a workaround.

Remote and specialist targets

Remote desktop, virtual machine, terminal, browser editor, and assistive-technology paths are useful reports. Identify the class without sharing host names, commands, account names, document titles, or private paths.

Clipboard restoration regression

If previous clipboard content is inserted, turn restoration off, remove the unintended text, and follow the recovery guide. Report that as a bug rather than a compatibility pass.

Community evidence

Share counts, not content

  1. Search for the same app and version

    Search the existing public issues for the target app and version. Add aggregate counts to a matching report instead of opening a duplicate.

  2. Submit one target-app report

    Open the compatibility report form. Passing results are useful because they provide the denominator that failure-only reports cannot.

  3. Review diagnostics before pasting

    Copy Diagnostics produces a privacy-safe summary if you choose to include it. Never add dictated or recognized text, clipboard contents, audio, dictionary or shortcut contents, screenshots with user data, credentials, titles, names, or private paths.
